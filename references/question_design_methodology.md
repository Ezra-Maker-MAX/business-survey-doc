# 问题设计方法论

当用户需要的业务领域**没有预置专家库**时，使用本方法论像领域专家一样即时设计调研问题。

## 核心思路：统一设计维度

任何业务领域的问题都可以从以下 7 个维度系统性设计，保证覆盖全面、不遗漏关键环节：

| 维度 | 要问什么 | 示例（以仓库管理为例） |
|---|---|---|
| **1. 管理对象** | 业务管什么"对象"？对象有哪些属性？ | 仓库有哪些？库位/货架如何划分？ |
| **2. 主数据与编码** | 对象如何编码？谁维护？数据源在哪？ | 物料/库位的编码规则？WMS主数据主源？ |
| **3. 核心流程** | 主流程如何跑？（申请→审批→执行→记录→闭环） | 入库流程：收货→质检→上架？ |
| **4. 数字化现状** | 现在用什么系统/工具？哪些环节手工？ | 用Excel还是WMS？条码扫描覆盖率？ |
| **5. 指标与KPI** | 管得好不好？用什么指标衡量？ | 库存准确率？周转天数？盘点差异率？ |
| **6. 合规与风控** | 有哪些制度/法规要求？风险点在哪？ | 先进先出FIFO？安全库存预警？ |
| **7. 痛点与需求** | 最大的痛点？最希望数字化解决什么？ | 找料慢？账实不符？缺料停线？ |

## 问题数量与等级配比

- **每子项 3-8 条问题**，按子项重要性分配
- **等级配比建议**：
  - 必问：约 50%（核心流程/主数据/对象管理）
  - 应问：约 30%（数字化现状/指标KPI）
  - 深挖：约 20%（合规风控/痛点根因）
- **每条问题三件套**：问题 + 建议追问 + 需要查看/索取（资料名）

## 设计步骤

### Step 1：解析业务范围
从用户描述中提取：
- 业务域（如"仓库管理"）
- 模块清单（如"入库、出库、库存、盘点"）
- 调研对象（公司/工厂名称）

### Step 2：识别预置专家库
调用 `domains.match_domain(用户描述)`：
- **命中** → 直接使用专家库，按需增删子项
- **未命中** → 进入 Step 3 即时设计

### Step 3：展开模块与子项
按"对象→流程→数字化→指标→合规→痛点"骨架展开：

```
模块：<业务主流程1> / <业务主流程2> / ...（通常 3-6 个模块）
每个模块下 2-4 个子项
```

示例（仓库管理）：
```
5.1 入库管理（收货/质检/上架）
5.2 出库管理（领料/发料/拣货）
5.3 库存管理（库位/批次/先进先出）
5.4 盘点管理（循环盘点/年终盘点）
5.5 库内作业（条码/叉车/AGV）
```

### Step 4：按7维度设计问题
对每个子项，逐维度问一遍（不必每维度都问，选择相关的 3-5 个）：

```python
# 以"入库管理"为例
sub_qs = [
    # 核心流程
    {'idx': 1, 'level': '必问', 'q': '入库流程是怎样的（到货→验收→质检→上架）？',
     'follow': '质检与入库的衔接？', 'need': '入库流程图'},
    # 数字化现状
    {'idx': 2, 'level': '必问', 'q': '入库单据如何记录（纸质/Excel/WMS）？',
     'follow': '条码扫描覆盖率？', 'need': '入库单样例'},
    # 指标
    {'idx': 3, 'level': '应问', 'q': '入库及时率/准确率如何统计？',
     'follow': '数据来源？', 'need': '入库报表'},
    # 痛点
    {'idx': 4, 'level': '深挖', 'q': '入库环节最大的痛点是什么？',
     'follow': '最希望数字化解决什么？', 'need': ''},
]
```

### Step 5：补齐领域配套数据
每个领域还需要：
- `resources`：资料索取清单（8-15条，标注优先级高/中/低）
- `interview_topics`：高层访谈主题（4-7个）
- `summary_dims`：调研总结维度（8-15条）
- `usage`：使用说明（含调研原则/特别关注）
- `it_systems` / `data_flows` / `reports`：系统/接口/报表清单

### Step 6：Q编号全局连续
所有模块的所有子项问题按 `1, 2, 3, ...` 连续编号，不跨子项跳号。

## 通用开场问题（任何领域适用）

每个子项建议至少包含1条"现状数字化"和1条"痛点需求"：
- `数字化现状：这个业务环节目前用什么方式管理（纸质/Excel/系统）？`
- `痛点需求：这个环节最大的痛点是什么？最希望系统解决什么问题？`

## 自检清单

生成问题后检查：
- [ ] 每子项 3-8 条问题
- [ ] Q编号全局连续（1,2,3...）
- [ ] 等级配比合理（必问≈50%）
- [ ] 每条问题有"建议追问"或"需要查看"（至少其一）
- [ ] 覆盖7维度中的至少4个
- [ ] 有完整的 resources/interview_topics/summary_dims/usage
- [ ] 文档结构与9章+5附录+签字栏一致

## 沉淀新专家库

当为一个新领域设计了完整问题库后，建议：
1. 复制 `domains/_template.py` 为 `domains/<新领域>.py`
2. 填入设计好的 DOMAIN 字典
3. 在 `domains/__init__.py` 的 `DOMAIN_REGISTRY` 注册
4. 下次同类调研直接命中专家库，质量更高
